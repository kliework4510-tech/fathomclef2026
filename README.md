# 🐟 FathomNetCLEF2026 深海生物検出

## 概要

Kaggleで開催されたFathomNetCLEF2026（CVPR-FGVC / LifeCLEF併催）に参加しました。

深海映像から32種の海洋生物を検出する物体検出タスクです。YOLO26、RT-DETR、RF-DETRの4モデルをアンサンブルし、102チーム中15位という結果でした。

## コンペティションの特徴

本コンペは訓練データのラベルが意図的に不完全な、Positive-Unlabeled（PU）設定である点が特徴です。

深海画像のアノテーションは海洋生物学者が行いますが、各研究者は自分の専門分野の生物にしかラベルを付けません。そのため1枚の画像内に「ラベルが付いている生物」と「写っているのにラベルがない生物」が混在します。

ラベルのない領域を背景として学習させると、正しい検出が誤りとして扱われ、検出漏れが増加します。上位でもmAPが0.1台に留まるのは、この構造的な難しさによるものです。

## 結果

| 項目 | 内容 |
|---|---|
| 順位 | 15位 / 102チーム（上位15%） |
| 評価指標 | mAP@50-95 |
| スコア | 0.1039 |

## データセット

| 項目 | 内容 |
|---|---|
| 訓練画像 | 6,463枚（4K / FHD混在） |
| テスト画像 | 1,425枚 |
| アノテーション | 22,225個 |
| クラス数 | 32クラス |
| フォーマット | COCO形式JSON |

## 前処理

- 4K / FHD画像を1024 × 1024へリサイズ
- COCO形式JSONをYOLO形式ラベルへ変換
- GroupKFoldによる交差検証用の分割

## モデル構成

4つのモデルを個別に学習し、アンサンブルしました。

| モデル | 入力サイズ | エポック数 | 学習環境 |
|---|---|---|---|
| YOLO26-m | 1024 | 30 | ローカル |
| YOLO26-l | 1024 | 30 | Kaggle T4 |
| RT-DETR | 1024 | 15 | ローカル |
| RF-DETR | - | 20 | ローカル |

CNNベースのYOLOとTransformerベースのDETRは誤検出の傾向が異なるため、組み合わせることで互いの弱点を補完できます。

## アンサンブル

- WBF（Weighted Boxes Fusion）で4モデルの予測を統合
- TTA：原画像、水平反転、896スケールの3種類
- モデル重み：[0.5, 0.5, 3.0, 2.0]（YOLO26-m : RT-DETR : RF-DETR : YOLO26-l）
- 信頼度しきい値：0.001
- WBF IoU：0.55

PU設定ではモデルの出力確信度が全体的に低くなるため、信頼度しきい値を通常より大幅に低く設定し、候補を広く残してWBF側で統合する方針を取りました。

## 疑似ラベル

高信頼度のテスト予測を訓練データに追加し、欠損しているラベルを補完しました。

欠損しているのはラベルであって生物そのものではないため、PU学習に対する直接的な対処となります。

## スコアの推移

| 構成 | mAP@50-95 |
|---|---|
| YOLO26-l 単体 | 0.0619 |
| YOLO26-m + RT-DETR | 0.0649 |
| RF-DETR 単体 | 0.0732 |
| 4モデルアンサンブル | 0.0891 |
| 疑似ラベル・重み調整後 | 0.1039 |

単体で最も高かったRF-DETRと比較して、最終的に約42%の改善となりました。

## 実行環境

| 環境 | スペック | 用途 |
|---|---|---|
| ローカル | RTX 4050 Laptop（VRAM 6GB） | YOLO26-m、RT-DETR、RF-DETR |
| Kaggle | Tesla T4 | YOLO26-l |

VRAM 6GBの制約下で1024 × 1024の学習を行うため、事前にリサイズしたデータセットを作成し、バッチサイズを調整して対応しました。大きいモデルはKaggleのT4に振り分けています。

## 処理の流れ

1. 4K / FHD画像を1024へリサイズし、YOLO形式ラベルへ変換
2. 4つの検出モデルを個別に学習
3. 高信頼度のテスト予測から疑似ラベルを生成し、訓練データへ追加
4. TTAを適用して各モデルで推論
5. WBFで4モデルの予測を統合し、提出ファイルを生成

## ファイル構成

- `sinkai1024.ipynb`：データ前処理（1024リサイズ、YOLO形式変換）
- `sinkai_x.ipynb`：モデル学習
- `pseudo_label.ipynb`：疑似ラベル生成
- `ensemble_pipeline.ipynb`：TTAとWBFによるアンサンブル推論、提出ファイル生成

## 学んだこと

- 異なるアーキテクチャを組み合わせるアンサンブルの有効性
- WBFの重み調整は再学習が不要なため、費用対効果の高いチューニング対象であること
- ラベルが不完全なデータへの対処方法（低しきい値、疑似ラベル）
- 限られたVRAMで大きな入力サイズの学習を回す工夫
- 疑似ラベルの反復適用は1回のみで、複数ラウンド試す余地があります
